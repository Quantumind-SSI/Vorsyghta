Vorsyghta CLI Command Masterclass

Prereqs / environment
- Create venv & install:
  python3 -m venv .venv
  source .venv/bin/activate
  python -m pip install --upgrade pip
  pip install -e .
  pip install -r requirements-mcp.txt || pip install asyncssh aiohttp mcp
- Verify dependencies:
  ./scripts/verify_flow.sh
- Important env vars:
  PROXMOX_HOST, PROXMOX_TOKEN_VALUE, PROXMOX_TOKEN_ID / PROXMOX_USER, PROXMOX_TOKEN_NAME
  VORSYGHTA_VM_USERNAME, VORSYGHTA_VM_PASSWORD
  Use config/mcp.example.yaml or demos/client_data/demo_config.yaml for --config

Template exploration & simulation (safe first)
- List templates:
  python -m vorsyghta --config demos/client_data/demo_config.yaml templates list-all
- Show/validate a template:
  python -m vorsyghta --config demos/client_data/demo_config.yaml templates show templates/executive_phishing.yaml --validate
- Validate all templates in folder:
  python -m vorsyghta --config demos/client_data/demo_config.yaml validate -d templates/
- Dry-run simulate (no LLM generation unless --live):
  python -m vorsyghta --config demos/client_data/demo_config.yaml simulate -s templates/executive_phishing.yaml --dry-run --preview
- Live simulate (may call LLM provider; set keys or run ollama):
  python -m vorsyghta --config demos/client_data/demo_config.yaml simulate -s templates/executive_phishing.yaml --live -o output.json
- Enrich template with client data:
  python -m vorsyghta --config demos/client_data/demo_config.yaml client-data enrich --tenant acme-demo --scenario templates/executive_phishing.yaml --output output/enriched.json
- Batch dry-run all templates:
  for t in templates/**/*.yaml; do python -m vorsyghta --config demos/client_data/demo_config.yaml simulate -s "$t" --dry-run --preview || echo "failed $t"; done

MCP server / toolserver & VM flow (template → VM → execute)
- Export MCP tools schema:
  python -m vorsyghta mcp export_schema -o /tmp/mcp_schema.json
- List MCP tools:
  python -m vorsyghta mcp tools
- Start MCP server (stdio transport):
  export PROXMOX_HOST=...; export PROXMOX_TOKEN_VALUE="..."
  python -m vorsyghta mcp start --config config/mcp.example.yaml
- Show MCP status:
  python -m vorsyghta mcp status
- Describe a specific tool:
  python -m vorsyghta mcp describe vm_execute

Atomic (programmatic) template→VM→execute example (safe)
- Programmatic create/execute (MCP server or Proxmox credentials required):
  export VORSYGHTA_VM_USERNAME=admin
  export VORSYGHTA_VM_PASSWORD=vulnerable123
  python - <<'PY'
import asyncio,json
from vorsyghta.mcp.server import VorsyghtaMCPServer
s = VorsyghtaMCPServer()
async def run():
  await s.connect_proxmox()
  # If template already mapped (e.g., ubuntu-target vmid 9001), run:
  res = await s.handle_tool_call('vm_execute', {'vm_id':'9001','command':'hostname'})
  print(res[0].text)
asyncio.run(run())
PY

Direct SSH test (bypass MCP, useful to confirm ssh/ip/creds)
- Quick SSH execute test:
  python - <<'PY'
import asyncio,json

print(json.dumps(asyncio.run(execute_ssh_command('10.0.100.5','uname -a',username='admin',password='vulnerable123')),indent=2))

Attack mapping & orchestration (programmatic)
- Map scenario → attack flow (AttackMapper):
  python - <<'PY'
from vorsyghta.integrations.attack_mapper import AttackMapper
mapper=AttackMapper()
scenario={'name':'Demo','threat_type':'spear_phishing','mitre_techniques':['T1566.001','T1003']}
flow=mapper.scenario_to_flow(scenario,target_info={'ip':'10.0.100.5','services':['http']})
print(flow['name']); print(flow['description'][:400])
PY
- Create an attack sequence (AttackOrchestrator):
  python - <<'PY'
import asyncio
from vorsyghta.core.attack_orchestrator import AttackOrchestrator
orch=AttackOrchestrator()
async def run():
  seq=await orch.create_attack_sequence_from_scenario('demo','10.0.100.5',['T1595','T1110'])
  print(seq)
asyncio.run(run())
PY
- Execute sequence (requires ToolServerClient reachable):
  Use AttackOrchestrator.execute_sequence(sequence_id) in an async script (see attack_orchestrator.py)

Troubleshooting tips
- Poetry system package error (dulwich mismatch): avoid system poetry. Use venv + pip install -e . or install Poetry via pipx or the official installer:
  python3 -m pip install --user pipx && python3 -m pipx ensurepath && pipx install poetry
  OR curl -sSL https://install.python-poetry.org | python3 -
- If MCP fails to connect to Proxmox: verify PROXMOX_HOST, PROXMOX_TOKEN_VALUE, network connectivity, and proxmox API reachability.
- If vm_execute returns "Could not get IP address": ensure VM is running and qemu-guest-agent installed.
- Logs & verification:
  ./scripts/installed_deps.txt
  demos/*/output/
  MCP server stdout (terminal where started)

Safe atomic runnable checklist (authorized lab, one-liner checklist)
1. Create venv, install, run deps check:
   python3 -m venv .venv && source .venv/bin/activate && pip install -e . && ./scripts/verify_flow.sh
2. Start local demo server (for client-data):
   bash demos/client_data/run_demo.sh
3. Dry-run simulate a template:
   python -m vorsyghta --config demos/client_data/demo_config.yaml simulate -s templates/sample_phishing_template.yaml --dry-run --preview
4. Start MCP server (if Proxmox integration needed):
   export PROXMOX_HOST=...; export PROXMOX_TOKEN_VALUE=...; python -m vorsyghta mcp start --config config/mcp.example.yaml
5. Confirm MCP tools available:
   python -m vorsyghta mcp tools
6. Create VM from template (via Proxmox template mapping) or use existing vmid:
   (Programmatic example in Atomic section above)
7. Confirm VM reachable over SSH (direct test):
   python - <<'PY' ... execute_ssh_command ... PY
8. Run safe command via vm_execute:
   see Atomic programmatic example above
9. Snapshot or destroy as required (vm_snapshot_* or vm_destroy via MCP server)

Notes
- Run commands only in isolated lab or authorized environments.
- Review config/mcp.example.yaml and templates before executing destructive or live flows.
